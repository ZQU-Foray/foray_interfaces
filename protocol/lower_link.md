# 上位机 ↔ 下位机链路协议

> **草案 v0.1** · 消息表待电控组逐条确认后冻结
> 机器可读定义 [`lower_link.yaml`](lower_link.yaml)（**唯一事实来源**）。
> 两侧代码由 [`../scripts/gen_lower_link.py`](../scripts/gen_lower_link.py) 生成，**禁止手写**。

## 1. 帧

```
┌─────────┬───────┬───────┬────────┬───────────────┬────────┐
│   SOF   │  LEN  │  SEQ  │ MSG_ID │    PAYLOAD    │ CRC16  │
│   2 B   │  1 B  │  1 B  │   1 B  │    0–250 B    │  2 B   │
│  A5 5A  │       │       │        │               │        │
└─────────┴───────┴───────┴────────┴───────────────┴────────┘
```

| 字段 | 规定 |
|---|---|
| `SOF` | 固定 `A5 5A`，失步后据此重新定位帧头 |
| `LEN` | PAYLOAD 字节数，0–250 |
| `SEQ` | 发送序号，每帧 +1 回绕。**收发两个方向各自独立计数** |
| `MSG_ID` | 消息号，见 §3 |
| `PAYLOAD` | 按 `MSG_ID` 解释，长度必须等于该消息的定义 |
| `CRC16` | CRC-16/CCITT-FALSE，**覆盖 `LEN`–`PAYLOAD`（不含 SOF）**，小端 |

**数据表示**：全部小端 · IEEE 754 单精度，禁用 `double` · `#pragma pack(1)` 无隐式填充 ·
角度用 `float` 弧度 · 帧总长上限 257 B。

## 2. 链路

物理层 **USB CDC**（虚拟串口，`/dev/ttyACM*`），Bulk 传输，不使用 RTS/CTS。

**USB CDC 对应用呈现的是字节流**——一次 `read()` 可能拿到半帧，也可能拿到三帧半，
不得假设一次读到整帧。帧界定与 CRC 都不能省。

**Linux 宿主侧必须做的三件事**：

| 项 | 规定 | 不做会怎样 |
|---|---|---|
| `latency_timer` | 设为 1 | `cdc_acm` 默认 16 ms，读方向攒批，实时预算归零 |
| 设备名 | udev 按 USB serial 绑定为 `/dev/foray_lower` | `/dev/ttyACM*` 编号随插拔顺序漂移 |
| 热插拔 | 当常态处理，HAL 需状态机 `OPEN → HANDSHAKE → RUNNING → LOST` | MCU 复位、线松、供电抖动都会让设备消失再出现 |

`LOST` 期间上位机停发指令，安全由下位机自主保证（见 §4）。

## 4. 安全与失效

### 失联后下位机必须自主执行 —— 硬路径

定时器跑在 MCU 上，**与 USB 中断无关**：USB 死了照常触发。动作必须实现，阈值为建议值。

| 动作 | 阈值 |
|---|---|
| 底盘速度归零 | 100 ms |
| **撤销开火授权**，摩擦轮停 | 200 ms |
| 云台停止接受指令，保持当前位置 | 500 ms |

### 不随消息表变动的约束

| 约束 |
|---|
| 承载**开火授权**的消息必须带周期心跳，**超时即撤销**——上位机可能已经死了 |
| 未授权时下位机**必须拒绝拨弹**，而不是仅在 UI 上体现 |
| 实弹发射能力必须可由下位机**独立切断**，不接受任何来源的覆盖 |
| 协议传**语义**，不传控制模式：位置环 / 速度环 / 连发上限 / 卡弹过热自保护归下位机 |
| **每一条控制类消息**都必须定义超时与超时动作，且由下位机执行 |
| 未知 `MSG_ID`、或 `LEN` 与消息定义不符 → **必须丢弃**，不得按猜测解释 |
| 裁判系统接在下位机由 MCU 转发，其串口接收与转发**不得阻塞控制下行** |

**开火安全三层独立**，任一层失效都不会失控发射：操作手授权（目标身份切换即失效）/
链路心跳超时撤销 / 下位机硬上限。

### 上位机侧的异常处置

| 异常 | 处置 |
|---|---|
| CRC 错 · `SEQ` 跳变 | 丢帧，计数上报 |
| 设备消失 | → `LOST`，进安全态，重连 |
| 重连成功 | 重新握手；**不自动恢复上一状态**，回 `IDLE` |

## 5. 版本

握手交换 `MAJOR.MINOR`：**`MAJOR` 不一致 ⇒ 拒绝进入 `RUNNING`**，进 `LOST` 并报错；
`MINOR` 不一致 ⇒ 允许运行，按较低版本的能力集工作。

| 改动 | 版本 |
|---|---|
| 新增消息号 · 在消息**末尾**追加字段 | MINOR |
| **修改已有消息的字段布局**（改类型、增删中间字段） | **MAJOR** |
| 改帧格式 / 字节序 / CRC | **MAJOR** |

破坏性变更走 **D2**：≥2 人评审 + 兼容性影响评估。
